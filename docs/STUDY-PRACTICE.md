# Study 연습 모드

기존 간격 반복 복습은 Study 홈 하단의 **저장 표현 복습**에서 유지한다. 현재 5단계의 지급 검증·채팅 API·운영 적용은 [STUDY-REWARD-PROOF.md](STUDY-REWARD-PROOF.md)를 함께 따른다.

6단계 **오답 복습**은 학습·프로필에서 `/study/mistakes`로 이동한다. 오답/정답 공개 문제를 유형·어투별로 다시 풀고 원래 풀이와 분리된 결과를 저장한다. AI 호출/추가 XP는 없으며 [기준·API·적용 안내](MISTAKE-REVIEW.md)를 따른다. 현재 빈 환경 초기화는 복습 테이블까지 14개다.

## 학습 규칙

- 어투 퀴즈: 5개 어투 중 정답을 포함한 4지선다. 첫 선택이 정답인 문제를 풀면 하루 한 번 20 XP.
- 단어 나열 퍼즐: 선택/제거/초기화/채점/정답 보기. 정답 공개 없이 완성하면 하루 한 번 25 XP. 오답 재시도는 허용하며 저장된 단어 순서와 비교한다.
- 오늘의 AI 문제는 유형별 영어 5문제다. 내 저장 문장은 최신 100개에서 최대 5문제를 선정한다. 퍼즐은 Intl.Segmenter로 2~24개 단어 블록을 사용한다.
- 롤플레이: 카페/회의/친구, 기존 7개 언어, 서버가 확인한 AI 응답 4회 완료 시 하루 한 번 35 XP. 채팅 본문은 모드 변경/페이지 이탈 시 사라지는 메모리 데이터다.
- 계정별로 퀴즈·퍼즐·채팅 각각 한국 날짜당 1회, 하루 최대 80 XP다. AI/저장 문제의 한도는 합산하며 이후에도 학습 결과는 계속 저장된다. [일일 제한 적용 안내](STUDY-POINTS.md)를 따른다.
- AI 문제와 해설은 틀릴 수 있다. 기존 복습 통계와 XP는 별도이며 프로필에서 XP 적립 기록을 확인할 수 있다.

## 오늘의 문제·풀이 결과 DB 저장 (3단계)

`daily_practice_sets`는 5단계부터 `(owner_id, day, kind, source)` unique로 계정·한국 날짜·퀴즈/퍼즐·출처(daily/saved)당 하나만 만든다. 생성 시작 시의 날짜를 유지하며 자정을 넘겨 응답해도 날짜가 바뀌지 않는다. 다음 날 학습을 시작하면 새 세트를 만든다. 예약 생성이나 무제한 재생성 버튼은 없다.

AI 응답을 기다리는 동안 DB 연결/트랜잭션을 점유하지 않는다. 생성 토큰과 180초 임대를 사용하고, 만료된 이전 요청은 새 문제를 덮어쓸 수 없다. 같은 문제를 만드는 동시 요청은 409로 안내하며, 완료된 세트는 AI 호출 없이 반환한다. 실패/만료 후 재시도할 수 있다.

내 계정의 최근 완료된 **30세트(최대 150문장, 퀴즈·퍼즐 합산)**를 DB에서 조회해 중복을 제외한다. 다른 계정의 문제는 AI에 전달하지 않는다. 정해진 예문을 순환하지 않지만 150문장보다 오래된 내용과 의미상의 유사성까지 보장하지는 않는다.

`daily_practice_answers`는 제출마다 요청 UUID, 문제 번호, 답안, 서버 채점 결과, 시도 횟수와 시각을 기록한다. 조회 응답에는 문제별 최신 제출 1건(최대 5건)을 담는다.

- 퀴즈: 첫 제출을 확정한다. 오답을 다시 정답으로 바꾸어 XP를 받을 수 없다.
- 퍼즐: 오답은 재시도 가능하며 이전 오답도 DB에 남는다. 정답/정답 보기 이후에는 결과를 변경하지 않는다.
- 문제 세트 행을 잠근 트랜잭션 안에서 제출과 정답 XP를 함께 저장한다. XP 실패 시 제출도 롤백한다. 응답 유실/동시 제출은 요청 UUID와 원장 unique 제약으로 중복 저장·적립을 막는다.
- XP 일일 한도는 **실제 지급 트랜잭션의 한국 날짜**를 따른다. 서로 다른 날짜의 세트를 같은 날 풀어도 한 유형의 XP는 한 번만 지급된다. 이미 완료한 답안을 다음 날 재전송해도 추가 적립되지 않는다. 프로필에는 실제 적립 시각이 표시된다.
- 다른 브라우저에서는 같은 계정으로 오늘의 문제를 다시 열어 최신 기록을 불러온다. 완료된 문제는 건너뛰고, 퍼즐의 마지막 제출이 오답이면 그 단어 배치부터 시작한다. 전체 완료 후에는 정답 수와 문제별 결과/해설을 볼 수 있다. 이미 열려 있는 다른 화면으로 실시간 푸시하지는 않는다.
- 저장 중에는 답안을 잠그고 다음 진행을 막는다. 실패 시 같은 UUID와 답안으로 수동 재시도한다. 아직 제출하지 않은 선택/입력, 서버에 도착하지 않은 요청은 DB에 없으므로 페이지 이탈 후 복원을 보장하지 않는다. 오늘의 답안에는 별도 브라우저 오프라인 큐를 만들지 않는다.
- 예전 `tonetalk-daily-ai-v1:*` 브라우저 캐시는 소유자를 확인할 수 없어 읽거나 이관하지 않는다. 자동 삭제도 하지 않는다. 기존 적립 원장은 그대로 유지한다.

5단계부터 내 저장 문장에도 위 서버 채점·첫 선택·정답 보기 저장을 적용한다. 당일 세트를 고정해 다시 시작하거나 저장 문장을 삭제해도 풀이가 초기화되지 않는다. 롤플레이는 원문 없이 서버 발급 세션의 횟수와 해시만 보관한다. 새 XP는 `/api/study/points`나 브라우저 완료 보고로 지급하지 않는다.

## API

모든 엔드포인트는 검증된 Supabase 사용자와 서버 owner 조건을 사용한다. 응답은 private/no-store. 웹의 `x-tonetalk-account`는 현재 로그인 계정과의 일치 확인용이며 소유권을 지정할 수 없다. 쓰기 요청에는 기존 same-origin 검사도 적용한다.

| 요청 | 입력 | 응답 |
| --- | --- | --- |
| `GET /api/study/daily?kind=quiz\|puzzle&source=daily\|saved` | 유형·출처(source 생략 시 daily) | `{practice: null 또는 {id,day,kind,source,phrases,results}, requestId}`. 조회만 하며 AI 호출 없음 |
| `POST /api/study/daily` | `{kind:"quiz"\|"puzzle",source?:"daily"\|"saved"}` | `{id,day,kind,source,phrases,results,requestId}`. 오늘 세트가 있으면 재사용. saved는 AI 호출 없음 |
| `PUT /api/study/daily` | `{eventId:UUID,setId:UUID,questionIndex:0..4,answer}` | `{result,awarded,points,totalPoints,requestId}` |

답안은 퀴즈 `{type:"quiz",tone}`, 퍼즐 `{type:"puzzle",order:[단어 원래 위치 인덱스...]}`, 정답 보기 `{type:"reveal"}` 중 하나다. 클라이언트의 owner/점수/채점 결과를 받지 않는다. 유형과 전체 단어 순열을 서버에서 검사한다.

잘못된 입력 400, 인증 필요 401, 계정/출처 불일치 403, 내 문제가 아님 404, 생성 중/UUID 충돌 409, 본문 초과 413, 요청 제한 429, DB 실패 500, AI 응답 오류 502. 생성 중에는 Retry-After: 3. 생성 요청은 새 세트에만 계정당 분당 4회, 답안 제출은 분당 60회 인스턴스 제한을 적용한다. 전역 악용 방지로 간주하지 않는다.

POST의 기존 `exclude` 필드는 구 클라이언트 호환을 위해 크기 제한 내에서 받지만 생성 제외 목록으로 신뢰하지 않는다. AI 처리는 기존 Gemini/Ollama provider와 전체 요청 예산(기본 150초)을 재사용한다.

`PUT /api/study/chat`으로 서버 sessionId를 먼저 발급받고, `POST`에 sessionId/eventId와 기존 scenario/language/messages를 제출한다. 응답은 진행 횟수·재처리 여부·AI 답변·포인트 확인을 포함한다. 이전 계약의 요청은 호환되지 않는다. 자세한 계약과 응답 유실 복구 범위는 [5단계 문서](STUDY-REWARD-PROOF.md)를 따른다.

## DB 적용 및 검증

마이그레이션: `supabase/migrations/20260915081206_daily_practice.sql`. 두 private 스키마를 대상으로 하는 추가 SQL이다. **단계별 적용 시 FOREACH 배열을 해당 스키마 하나로 좁힌다.** dev → 테스트 → prod → 앱 배포 순서를 따른다. 기존 데이터를 삭제하거나 legacy Drizzle public 이력을 재생하지 않는다. 테이블 2개와 인덱스/FK만 추가하고 RLS 활성화·PUBLIC/anon/authenticated 권한 회수를 유지한다.

2026-09-15: 동일 SQL의 배열을 `['tonetalk_dev']`로 제한하여 트랜잭션으로 적용했다. 운영 스키마는 변경하지 않았고 당시 이 두 테이블이 없었다. **Vercel에 이 코드를 배포하기 전 운영 마이그레이션이 필요하다.** 이후 4·5·6단계도 개발에만 적용했다. 현재 빈 스키마 초기화는 오답 복습까지 14개 테이블을 출력하며 최신 적용 순서는 [6단계 문서](MISTAKE-REVIEW.md)를 따른다.

검증 명령:

```bash
pnpm test:run
pnpm lint
pnpm build
DAILY_PRACTICE_DB_TEST=1 BOOTSTRAP_DB_TEST=1 node --env-file=.env.local node_modules/vitest/vitest.mjs run tests/daily-practice-db.test.ts tests/bootstrap-db.test.ts
```

DB 테스트는 명시적 dev 연결만 허용한다. 임의 UUID의 테스트 행만 만들고 cascade로 정리한다. 실제 DB/API를 사용하며 Auth 사용자 검증과 AI 출력만 모킹한다. 따라서 실제 공급자의 문제 품질이나 인증 공급자 가용성을 확인하는 테스트는 아니다. 문제 생성 중복, 계정 격리, 복원, 동시 제출, 보상 원자성, 날짜 경계, 임대 실패/만료, RLS를 검증한다.

2026-09-15 검증 결과: 일반 테스트 145개 통과(선택 실행 DB 테스트 등 17개 제외), 실제 개발 DB 테스트 12개 통과(일일 문제 7·기존 XP 4·빈 스키마 초기화 1). 타입 검사·ESLint·Next.js 프로덕션 빌드 통과. 이번 DB 테스트가 만든 임의 UUID 계정과 학습 행은 정리했다. 2단계에서 만든 실제 Auth 테스트 계정은 삭제하지 않았다. 이번 브라우저 조작은 중단되어 Chrome/Safari UI 검증 완료로 간주하지 않는다. 커밋·푸시·운영 DB 적용·Vercel 배포는 수행하지 않았다.

저장된 문제/답안/원장은 보존하며 테이블 drop이나 사용자 기록 삭제를 롤백 절차로 사용하지 않는다. **5단계 적용 후에는 source 고유 인덱스가 바뀌므로 단순한 이전 앱 복귀는 불가능하다.** 새 DB 계약을 사용하는 호환 코드로 복구해야 한다. 세트에는 학습용 정답/해설도 포함되므로 부정행위 방지 시험 시스템으로 간주하지 않는다.
