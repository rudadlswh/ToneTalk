# Lyrics MVP

## 학습 카드 상세 보기

- 참고 이미지처럼 로마자 → 큰 원문 → 하이라이트 번역 → 한글 발음 순서로 표시.
- 번역 후 줄별 `단어 · 문법 자세히 보기`로 추가 해설 요청. 일본어 한자에는 `<ruby>/<rt>` 후리가나, 최대 8개 핵심 단어·표현에는 읽는 법·한글 발음·한국어 뜻·품사/활용 설명, 마지막에 문장 뉘앙스 표시. 해설은 번역 언어와 무관하게 한국어.
- 추가 API: `POST /api/lyrics`에 `{action: "explain", sourceLanguage: "ja", text: "青い空を見た"}`. 응답 `{explanation: {segments: [{text, reading}], words: [{text, reading, hangulPronunciation, meaning, grammar}], nuance}, requestId}`.
- 요청 중 입력/언어 변경 및 다른 생성 요청을 막고 취소 가능. 해설 실패 시 기본 번역은 유지, 줄별 재시도 제공. 완료한 해설은 현재 페이지에서 재사용하며 결과 복사에 포함. 입력 변경·페이지 이탈 시 제거.
- 원문 재조합 완전 일치, 단어의 원문 포함 여부, 중복, 일본어 후리가나 문자, 한글 해설 형식 검사. 후리가나·단어 의미의 언어학적 정확성을 보장하는 사전은 아니며 작은 모델의 오류 가능성을 UI에 표시.
- 자동 전체 해설 생성은 CPU 대기 시간을 크게 늘리므로 요청한 줄만 별도로 처리. 동일 페이지에서는 번역/해설을 한 번에 하나만 요청.

- `/lyrics`: 직접 붙여 넣은 가사를 원문 / 번역 / 원문 로마자·한글 발음으로 표시. 두 발음 모두 기본 표시, 개별 숨김 가능. 원문 TTS는 기존 useSpeech 사용(노래 재생 아님).
- 가사 언어 자동 감지 기본, 번역 언어 한국어 기본. 기존 7개 언어 선택. 혼합 언어는 줄별 감지하나 한 줄 안의 혼합 발음 정확도는 보장하지 않음.
- 최대 6,000자·빈 줄 포함 80줄·줄당 200자. 빈 줄과 반복 후렴 위치 유지. 창작 예문 제공. 노래 검색/가사 수집/자동 완성 없음.
- 클라이언트가 비어 있지 않은 줄을 최대 10줄씩 순차 `POST /api/lyrics` 호출. 완료된 묶음부터 표시. 중단·실패 시 결과 유지, 이어서 번역은 미완료 줄만 전송. 입력/언어 변경 시 결과 초기화. 탭을 떠나거나 새로고침하면 사라짐. DB/브라우저 영구 저장 없음.
- 요청: `{sourceLanguage: "auto", targetLanguage: "ko", lines: [{id: 0, text: "Morning light"}]}`
- 응답: `{lines: [{id: 0, sourceLanguage: "en", translation: "아침 햇살", romanization: "Morning light", hangulPronunciation: "모닝 라이트"}], requestId}`
- 줄 ID 대응/중복/개수/발음 문자/출력 크기 검증. 번역 언어는 문자 체계 기반 휴리스틱이며 의미·발음 정확성을 보장하지 않음. 작은 LLM은 검증 실패(502) 가능. 재시도는 사용자 선택이며 자동 반복 호출하지 않음.
- [Ollama structured outputs](https://docs.ollama.com/capabilities/structured-outputs)의 JSON Schema로 줄 ID·필수 필드·한글 발음 문자를 생성 단계에서도 제한. 원문 발음과 번역문 발음을 혼동하지 않도록 영어·일본어 예시를 프롬프트에 제공.
- 기존 서버 전용 Ollama URL·모델·Basic Auth 설정 재사용. 요청당 제한은 환경값과 170초 중 작은 값, Vercel 함수 180초. 별도 DB 스키마·환경변수·패키지 추가 없음.
- API는 6KB 스트림 입력 상한, 동일 Origin 검사, 프로세스별 IP 30회/분 제한. 400 입력, 403 출처, 413 크기, 429 빈도, 502 모델 형식, 503 연결/시간 초과. 가사와 자격증명을 앱 로그에 남기지 않음. 인증·분산 rate limit·전역 LLM 동시성 제한은 기존 단일 사용자 구조의 한계로 남아 있음.
- 처리 시간을 줄이기 위해 5가지 어투 생성은 하지 않음. 각 10줄 묶음만 문맥으로 사용하므로 전체 곡 맥락에 따른 해석은 제한적. 긴 가사는 여러 묶음으로 나누며, 한 묶음 실패 시 완료된 결과를 유지하고 이어서 번역할 수 있음.

## 확인

`pnpm test:run`, `pnpm lint`, `pnpm build`

수동: 예문 → 번역 → 부분 진행 → 중단/재개 → 입력 변경 시 초기화 → 발음 토글/복사 → 빈 줄·후렴 보존 → 모바일 5개 메뉴. 실제 AI 품질과 TTS 음성 지원은 사용 중인 모델·브라우저로 별도 확인.
