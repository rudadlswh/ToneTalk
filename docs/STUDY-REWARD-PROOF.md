웹 프로젝트 `/Users/chogyeongmin/develop/tonetalk` 대상이다. XP는 퀴즈 첫 선택 정답 20, 정답을 보지 않은 퍼즐 완성 25, 서버가 확인한 롤플레이 4회 응답 35로 유지한다. 기존 원장/프로필 적립 기록은 변경하거나 소급 취소하지 않는다. 새 라이브러리·AI 채점 호출 없이 기존 답안 저장과 DB 트랜잭션을 재사용한다.

## 지급 경로

### 저장 문장도 서버 채점

`daily_practice_sets.source`에 `daily`/`saved`를 추가했다. 계정·한국 날짜·유형·출처별로 세트 하나를 보관한다. 이전 행은 `daily`로 유지한다. 저장 문장은 최신 100개 중 기존 선정 방식으로 최대 5개를 골라 스냅샷을 저장하고, 퍼즐은 해당 언어로 분리한 2~24개 단어 블록만 사용한다. 이 경로는 AI를 호출하지 않는다.

당일 저장 문장 세트를 다시 열거나 원래 저장 문장을 삭제해도 첫 선택/정답 보기 이력이 초기화되지 않는다. 저장 문장 ID와 세트 날짜는 기존 완료 중복 방지 근거로 유지한다. 일일 지급 한도는 문제 세트 날짜가 아닌 실제 DB 지급 시각의 한국 날짜(`credited_on`)를 따른다. 프로필에도 실제 지급 시각이 표시된다.

`GET /api/study/daily?kind=quiz|puzzle&source=daily|saved`, `POST /api/study/daily`의 `{kind,source}`를 사용한다. source 생략은 이전처럼 daily다. DTO에도 source가 포함된다. 저장 문장이 없으면 422/NO_SAVED_PRACTICE이며 서버가 임의의 예문으로 대체하지 않는다. `PUT` 답안 계약은 동일하다.

### 채팅: 원문을 저장하지 않는 진행 검증

1. `PUT /api/study/chat`에 `{scenario,language}`를 보내 `{sessionId,requestId}`를 받는다. 서버가 계정에 묶인 UUID를 발급한다.
2. `POST /api/study/chat`에 `{sessionId,eventId,scenario,language,messages:[{role,content}]}`를 보낸다. eventId는 한 발화의 재시도 동안 유지한다.
3. 서버는 이전까지 확정된 대화의 해시·발화 순서·상황·언어·소유자를 확인하고 세션의 생성권을 확보한다. 다른 계정/가짜 세션은 404, 변조·건너뛰기는 409이며 AI를 호출하지 않는다.
4. DB 트랜잭션 밖에서 기존 AI 제한·시간 예산을 적용해 응답을 생성한다. 이후 짧은 트랜잭션으로 응답 횟수·해시·요청 ID를 갱신하고 4회째만 XP를 기록한다. XP 저장 실패 시 횟수도 롤백한다.

정상 응답은 `{sessionId,turns,replayed:false,response:{reply,feedback,suggestion},points,totalPoints,requestId}`다. 클라이언트 횟수나 지급 금액은 신뢰하지 않는다. 동일 세션의 동시 요청은 409/CHAT_BUSY, 생성 임대는 200초이며 만료된 작업은 결과를 덮어쓸 수 없다. 새 발화는 세션 시작 후 24시간 안에만 가능하다. 세션 생성은 계정당 분당 10개로 DB에서 제한하며 기존 라우트 요청 제한도 유지한다.

마지막으로 확정된 요청과 같은 eventId·내용의 재전송은 AI 호출 없이 `{replayed:true,response:null,points:0,...}`로 확인한다. 대화 원문이 없으므로 유실된 답변은 복원하지 못한다. 화면에서 이 사실과 새 대화 시작을 안내하며 확정된 XP는 그대로 둔다. 실패/취소 후에는 같은 요청을 재확인하거나 새 대화를 시작한다. 페이지를 닫거나 모드를 바꾸면 대화 화면과 미확인 요청은 사라진다. 이전 발화를 모두 보관하는 재시도 원장은 만들지 않았으므로, 최신 발화보다 오래된 요청은 충돌로 처리한다.

`study_chat_sessions`에는 소유자, 상황·언어, 횟수, SHA-256 해시, 요청/임대 식별자, 시각만 보관한다. 사용자 메시지·AI 답변·피드백 본문은 DB나 브라우저 저장소에 넣지 않는다. AI 공급자로의 전송과 공급자 데이터 정책은 기존 설정을 따른다. 해시가 익명화를 보장하는 것은 아니므로 계정 범위와 private 스키마 접근 통제를 유지한다. 만료는 새 발화 금지이며 행의 자동 삭제를 의미하지 않는다. 메타데이터는 계정 삭제 시 cascade로 제거되고 별도 보관기한 정리 작업은 아직 없다.

### 이전 미저장 큐

`POST /api/study/points`는 기존 입력 형식을 받되 원장에 없는 요청은 409/POINTS_PROOF_REQUIRED, retryable=false다. UUID를 매번 바꿔 보내거나 임의 활동 ID로 새 XP를 생성할 수 없다. 이미 적립된 정확한 요청은 200/awarded=false로 확인한다.

브라우저 큐의 증빙 없는 요청은 자동 삭제하거나 무한 재전송하지 않고 경고와 함께 보관한다. 해당 요청 때문에 뒤에 있는 기존 적립 확인이 막히지 않는다. 계정 격리와 계정 일치 헤더 검증을 유지한다. 새 화면은 이 큐로 지급을 요청하지 않는다. 오늘/저장 문제의 미확인 답안은 같은 화면에서 재시도하고, 이미 서버에 저장된 풀이 결과는 다시 조회한다.

- 스키마 변경과 웹 배포를 짧은 점검 구간에 함께 진행하고, 기존에 열린 웹 화면은 새로고침한다. 이전 채팅 계약에는 sessionId/eventId가 없어 400이 되므로 새 API 계약으로 클라이언트를 맞춰야 한다. 별도 Expo 프로젝트는 이번 작업에서 수정하지 않았다.
- 커밋·푸시·운영 DB 변경·Vercel 배포는 하지 않았다.
