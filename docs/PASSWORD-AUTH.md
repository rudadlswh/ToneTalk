# 아이디·비밀번호 로그인

기존 이메일 링크 로그인 UI/API를 아이디·비밀번호 가입/로그인으로 대체합니다.
Supabase Auth의 UUID 및 기존 사용자별 데이터 격리는 유지합니다. 비밀번호를 앱 DB나 로그에 저장하지 않습니다.

## 필수 설정

Supabase Authentication의 Email provider는 켠 상태로 **Confirm email을 끄세요**.
dev/prod는 같은 Supabase 프로젝트를 사용하므로 이 설정은 두 환경에 함께 적용됩니다.
설정 변경 전 가입 테스트를 하지 마세요. 확인 메일을 요구하는 계정이 생길 수 있습니다.

아이디는 소문자로 정규화한 영문/숫자/밑줄 4~24자입니다. 내부 Auth 식별자는
`아이디@users.tonetalk.invalid`이며 실제 이메일 주소가 아닙니다. 비밀번호는 8~128자입니다.
`POST /api/auth/signup`, `POST /api/auth/login`은 `{username,password}`를 받습니다.
가입 성공 시 자동 로그인하며 세션은 HttpOnly 쿠키로 유지됩니다.

기존 이메일 계정 데이터는 삭제/자동 이전하지 않습니다. 이메일 계정의 신규 아이디 연결과
분실 비밀번호 복구는 별도 본인 확인 절차가 필요하며 이번 MVP에는 포함하지 않습니다.
메일 콜백은 기존 링크 호환용으로 남아 있지만 새 로그인에서 사용하지 않습니다.
앱 시도 제한은 인스턴스 메모리 기반이며 Supabase 자체 제한도 적용됩니다.
