# 오답 복습 (6단계)

대상: `/Users/chogyeongmin/develop/tonetalk` 웹 프로젝트. 학습 홈의 **오답 복습**, 프로필의 **오답 복습으로 이어가기**에서 `/study/mistakes`로 이동한다. 로그인 후 목적지 복귀와 세션 갱신 대상에도 이 경로를 추가했다. 별도 Expo 프로젝트는 수정하지 않았다.

## 학습 규칙

- 오늘의 AI 문제와 내 저장 문장 세트의 기존 DB 답안을 사용한다. 퀴즈 오답, 퍼즐 오답 또는 정답 공개 기록이 한 번이라도 있으면 대상이다. 이후 원래 퍼즐을 맞혔어도 복습 대상에 포함하며, 같은 세트·문제는 한 번만 표시한다.
- 학습 유형(퀴즈/퍼즐), 어투 5종, 복습 상태(필요/완료/전체)를 선택할 수 있다. 기본은 복습 필요이며 문제 날짜 최신순으로 20개씩 가져온다.
- 최신 **복습** 답안이 정답이면 완료, 오답/정답 공개 또는 미복습이면 필요 상태다. 완료한 문제도 전체/완료 목록에서 다시 연습할 수 있다. 이후 복습에서 틀리거나 정답을 공개하면 다시 필요 상태가 된다. 목록에는 최신 복습 결과와 누적 제출 횟수가 표시된다.
- 기존 퀴즈·퍼즐 화면과 서버 채점 함수를 재사용한다. AI 호출이나 문제 복제는 없다. 새 정답 보기 후에도 다시 풀 수 있으며, 복습은 항상 **추가 XP 0**이다.
- 원래 퀴즈의 첫 선택, 퍼즐의 정답 공개, 일일 XP 제한과 적립 내역은 바꾸지 않는다. 복습에서 정답을 맞혀도 원래 문제를 정답으로 덮거나 소급 XP를 지급하지 않는다. 원래 퍼즐에서 아직 정답을 공개하지 않았다면 원래 학습 화면의 기존 지급 규칙은 그대로다.
- 저장 문장을 삭제해도 기존 문제 세트 스냅샷이 남아 있으면 복습할 수 있다. DB에 저장되기 전의 예전 브라우저 전용 풀이 이력은 복원/이관하지 않는다.

## 저장·보안

`mistake_review_answers` 하나만 추가한다. `id`(재시도 UUID), `set_id`, `question_index`, `attempt_number`, `answer`, `outcome`, `created_at`을 기록한다. 문제별 제출 순서에 unique index가 있으며 세트 삭제 시 cascade한다. 사용자 소유권은 부모 세트의 owner를 통해 검증한다. 원래 `daily_practice_answers`와 XP 원장은 읽기만 한다.

서버는 검증된 로그인 계정의 세트 행을 잠근 짧은 트랜잭션에서 오답 이력을 확인하고 저장된 문장으로 채점한다. 클라이언트의 사용자 ID·정답 주장·XP는 받지 않는다. 같은 요청 UUID와 답안의 재전송은 기존 결과를 반환하며 다른 답안으로 같은 UUID를 쓰면 409다. 원래 학습과 복습의 동시 제출도 같은 부모 행 잠금으로 순서를 보장한다. 새 요청은 별도 시도로 저장한다.

RLS를 활성화하고 PUBLIC/anon/authenticated의 테이블 직접 접근을 막는다. API는 계정 조건, same-origin 쓰기 제한, 웹의 계정 일치 헤더, 2 KB 입력 제한을 유지한다. 60회/분 인스턴스별 제출 제한은 보조 장치이며 전역 남용 방지 시스템은 아니다. 로그에는 요청 ID만 남기며 답안·원문·토큰을 출력하지 않는다.

오답 목록은 기존 답안에서 요청 계정의 기록만 조회해 계산한다. 정렬 키 `(day,set_id,question_index)` 내림차순의 커서 조회다. 다른 계정의 커서로도 소유권 범위를 벗어나지 못한다. 전체 이력을 브라우저로 보내지 않지만 매우 큰 계정 이력에서는 집계 비용을 측정한 뒤 별도 큐/인덱스 최적화를 검토한다. 현재 규모에는 추가 캐시·서버·의존성을 넣지 않았다.

## API

| 요청 | 입력 | 응답 |
| --- | --- | --- |
| `GET /api/study/mistakes` | `kind=all|quiz|puzzle`, `tone=all|casual|polite|formal|slang|written`, `status=pending|resolved|all`, 선택 cursor | `{items:[{setId,day,kind,source,questionIndex,phrase,original,review}],nextCursor,requestId}` |
| `POST /api/study/mistakes` | 기존 답안 형식 `{eventId,setId,questionIndex,answer}` | `{result:{eventId,questionIndex,answer,outcome,attemptNumber},replayed,points:0,requestId}` |

original은 가장 최근의 원래 오답/정답 공개, review는 최신 복습 제출 또는 null이다. 원래 퍼즐을 나중에 맞혔을 때도 당시 헷갈렸던 기록을 남긴다. 답안 형식은 퀴즈 `{type:"quiz",tone}`, 퍼즐 `{type:"puzzle",order:[원래 단어 인덱스...]}`, 정답 보기 `{type:"reveal"}`다.

잘못된 입력 400, 비로그인 401, 계정·출처 불일치 403, 없는/타인/오답 아닌 문제 404, 요청 UUID 충돌 409, 본문 초과 413, 요청 제한 429(Retry-After), DB 오류 500. 응답은 private/no-store이고 빈 기록과 장애를 구분한다.

## 실패와 재접속

저장 중 답안과 목록 이동 버튼을 잠근다. 실패하면 입력을 유지하고 **같은 답안 다시 저장**으로 동일 UUID를 전송한다. 서버 처리 후 응답이 유실돼도 중복 기록/적립되지 않는다. 페이지를 떠나기 전까지 확인되지 않은 답안은 별도 오프라인 큐에 보관하지 않으며 화면에서 경고한다. DB에 저장된 최신 결과·시도 횟수는 새로고침/다른 브라우저에서도 조회할 수 있다. 아직 제출하지 않은 단어 배치는 복원하지 않는다.

필터 변경으로 취소된 과거 조회 응답이 새 목록을 덮지 못한다. 더 보기 실패 시 기존 목록은 유지하고 같은 커서를 재시도한다. 실시간으로 다른 브라우저에 변경을 밀어 넣지는 않으므로 재조회가 필요하다. 복습 기록 상세 타임라인·간격 반복 예약·알림·추가 XP는 이번 범위가 아니다.
